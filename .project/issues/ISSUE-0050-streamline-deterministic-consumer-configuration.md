# Streamline deterministic consumer configuration

## Destination

A complete upstream release configures a consumer through integrity-based discovery, conditional backend inspection, deterministic reviewable planning, and transactional application without hand-authoring canonical YAML or guidance.

## Notes

Implementation occurs only in `synthlike/agent-workflows`; never patch an installed consumer's `configure-workflows`, because doing so invalidates its embedded manifest. Preserve ARP-0007: lifecycle planning and apply may write consumer configuration, guidance, and exact backend assets but never install, replace, or remove skill directories.

Pi discovery distinguishes installed integrity, model invocation eligibility, and runtime prompt visibility. Manifest metadata can declare invocation policy but cannot prove what a running model saw. Local-only planning must not invoke `gh` or `bearcli`. GitHub label provisioning remains separately approved external work.

## Decisions so far

- Manifest format 2 records `model_invocation` as `enabled` or `manual`; inspection reports installed, model-invocable, and manual-invocation sets without claiming runtime prompt visibility.
- Pi may treat a complete integrity-checked installation under its project discovery root as discovery evidence when files existed at startup.
- Consumer plans bind exact generated bytes, copied source/destination hashes, prior target state, lazy directories, and a canonical digest.
- Apply stages and rechecks all planned files, rolls back caught failures, writes no record destinations, and verifies before success.
- Consumer configuration apply never mutates distribution-managed skill directories.
- The next unpublished release is `v0.5.0`, not `v0.5.1`; deterministic plan/apply follows in `v0.6.0`.

## Execution plan

Independent first slices:

- Correct discovery semantics and inspect backends conditionally.
- Bundle canonical consumer guidance templates.

Dependent slices:

- Publish the complete v0.5.0 release after Bear documentation/smoke completion and both first slices.
- Generate deterministic consumer configuration plans after both first slices.
- Apply approved consumer configuration plans transactionally.
- Route configure-workflows through plan and apply.
- Publish deterministic configuration as v0.6.0 after v0.5.0 and the plan/apply cutover.

None.

## Out of scope

- Patching installed consumer skill files.
- Installing, updating, or removing skill directories.
- Automatic GitHub label provisioning within consumer apply.
- Schema migration, cross-backend record migration, or record destination creation.
- Claiming that static manifest metadata proves runtime model prompt contents.
