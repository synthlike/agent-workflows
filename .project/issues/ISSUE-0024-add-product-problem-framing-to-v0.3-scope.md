# Add product-problem framing to v0.3 scope

## Parent

[RFC-0004: Focus v0.3 on project foundations and feedback workflows](../../docs/rfcs/RFC-0004-focus-v0.3-on-project-feedback-workflows.md)

## What to build

Refine the accepted v0.3 scope with a seventh workflow that helps a founder frame, challenge, and empirically test a startup problem hypothesis before product specification or technical architecture.

## Acceptance criteria

- [x] An accepted RFC records why product-problem framing belongs in v0.3 and distinguishes it from existing clarification, questionnaire, research, and planning workflows.
- [x] A consequential roadmap refinement is recorded as an ARP without rewriting ARP-0005 history.
- [x] The v0.3 specification defines founder interview, problem brief, validation-plan, evidence-state, reassessment, authority, and exclusion boundaries.
- [x] Release scope, skill count, and validation issue dependencies are aligned before implementation.
- [x] The decision owner reviews and approves the amended specification.

## Blocked by

None.

## Out of scope

- Implementing `frame-product-problem`.
- Performing founder or customer discovery for a consumer project.
- Reopening the six already accepted and implemented v0.3 workflows.
